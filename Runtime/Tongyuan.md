## 知识点（可继续补充）

### 核心概念
- **执行图（Execution Graph）**：将复杂 Agent 任务抽象为带依赖关系的图结构，节点是任务，边是依赖关系。
- **任务编排（Task Orchestration）**：按依赖关系组织、调度任务的执行顺序与并行方式。
- **Agent Runtime（图执行引擎）**：负责节点调度、依赖解析、执行状态管理的运行时引擎。

### 图与调度算法
- **DAG（有向无环图）**：任务依赖的常见表达形式，边表示数据依赖或控制依赖。
- **拓扑排序（Topological Sort）**：对 DAG 节点排序，保证前驱任务先执行。
- **数据依赖 / 控制依赖**：数据依赖指任务需要前序任务的输出；控制依赖指执行顺序/条件的约束。
- **节点调度（Node Scheduling）**：决定节点在何时、由哪个执行单元运行。
- **并行执行**：识别无依赖的节点并发执行，提高吞吐。
- **关键路径优化（Critical Path）**：找出决定总时长的任务链，针对性优化以缩短整体执行时间。
- **状态管理**：跟踪节点执行状态（就绪/运行/成功/失败）及任务图整体状态。

### 执行成本与增量计算
- **LLM 调用成本**：减少不必要的 LLM 调用和上下文重复传递可显著降低成本与延迟。
- **确定性任务下沉（Downshift to Runtime）**：把确定性的工具执行、状态判断、流程控制交给 Runtime 执行，而非每次调用 LLM。
- **状态缓存 / 结果复用**：缓存节点结果，避免重复计算。
- **失败恢复**：节点失败后的回退与重试策略。
- **增量重执行**：局部任务变化时只重跑受影响部分，避免整条任务链重新执行。

- **profiling**：系统性能剖析，定位瓶颈。

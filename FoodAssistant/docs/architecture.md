# 系统架构

## 1. 分层

| 层 | 职责 | 不应负责 |
|---|---|---|
| 入口层 | 接收用户问题、加载安全配置、展示结果 | 直接访问供应商或菜谱文件 |
| Agent 编排层 | 维护消息与步骤状态、决定继续调用工具还是结束 | 实现具体工具业务逻辑 |
| 模型适配层 | 把统一请求转换为各供应商请求，归一化响应与错误 | 决定付费策略 |
| 工具层 | 执行天气、食材、检索和菜谱查询 | 修改系统文件或访问无关网络 |
| 数据层 | 提供版本化的菜谱和模拟库存 | 保存真实密钥或用户隐私 |
| 评测与观测层 | 记录脱敏指标、运行共享用例、比较分支 | 记录完整敏感载荷 |

## 2. 单次请求流程

1. 入口层验证配置并建立请求级预算和最大步骤数。
2. Agent 把用户目标和可用工具说明发送给模型适配层。
3. 模型返回工具调用请求或最终回答。
4. 编排层校验工具名与参数，再执行白名单工具。
5. 工具返回结构化成功或错误结果，编排层将其作为观察结果加入状态。
6. 重复第 2 至第 5 步，直到完成、超时、超预算或达到最大步骤数。
7. 输出回答以及脱敏的运行摘要。

## 3. 跨分支不变量

- 相同的工具名称、输入含义、输出语义和错误分类；
- 相同的数据集版本、用户问题和评测标准；
- 相同的最大步骤、超时和付费回退默认值；
- 相同的最终回答最低内容要求。

只有编排实现方式不同：分支 1 使用显式循环，分支 2 使用状态图，分支 3 使用 TypeScript 显式循环。

## 4. 状态边界

MVP 只保留单次请求内的短期状态，不做跨会话长期记忆。未来如增加记忆，必须先定义保存内容、过期时间、删除方式、隐私边界和评测方法。

## 5. 错误分类

- `configuration_error`：缺少供应商或模型配置；
- `authentication_error`：密钥无效，不应自动切换到付费供应商；
- `rate_limit`：触发限流，可进行受控退避；
- `timeout`：模型或工具超时；
- `invalid_tool_request`：工具名或参数不符合契约；
- `not_found`：没有找到食材或菜谱；
- `budget_exceeded`：达到调用或费用上限；
- `internal_error`：未分类的本地错误。

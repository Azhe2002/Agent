# ADR 0004：手写分支优先使用 Python 标准库

- 状态：已接受
- 日期：2026-08-27

## 背景

分支 1 的学习目标是直接理解模型调用、工具协议、循环终止、错误处理和安全边界。若初版同时引入 HTTP SDK、配置库和 Agent 框架，初学者很难区分哪些行为来自协议、哪些来自依赖封装。

## 决策

分支 1 初版只使用 Python 标准库：`urllib` 调用 NVIDIA 的 OpenAI 兼容接口，`json` 处理协议，少量显式代码加载配置、校验工具参数并运行 Agent Loop。模型供应商固定为 NVIDIA，付费回退保持关闭。

共享数据、工具契约和评测用例不依赖这个选择。后续分支仍可使用各自适合的 SDK 或框架，但行为必须与共享契约一致。

## 影响

- 优点：无需安装依赖，协议流向可见，适合逐行学习和单元测试；
- 代价：需自行维护有限的 HTTP 错误分类和响应校验，不覆盖 SDK 的流式输出、重试或遥测能力；
- 约束：初版仅实现当前任务需要的最小兼容面；扩展前先用评测证明需求，不提前抽象；
- 退出条件：当流式输出、复杂重试或多供应商成为明确需求时，新增 ADR 再评估官方 SDK。

# ADR 0006：Web 供应商切换使用逐请求白名单

- 状态：已接受
- 日期：2026-09-01

## 背景

本地 Web 测试台需要在 DeepSeek、MiMo、Kimi、NVIDIA 之间对比，但不能让浏览器任意指定供应商或模型，也不能因此打开自动付费回退。选择结果还应在响应中可观察，避免界面显示与真实调用不一致。

## 决策

Web 服务只暴露 `deepseek`、`mimo`、`kimi`、`nvidia` 四个固定选项，分别绑定 DeepSeek V4 Flash、MiMo V2.5、Kimi K2.6 与 NVIDIA GPT-OSS 20B。只读 `/api/providers` 接口返回各选项的配置状态与公开模型 ID；没有合法本地密钥配置的选项会被禁用。每次 `/api/chat` 请求提交供应商 ID，服务端再次校验后为本次请求加载该供应商的独立密钥、官方 HTTPS 域名和白名单模型。

四个供应商都使用同一个标准库 OpenAI Chat Completions 适配器和相同工具契约，但允许适配必要的请求字段差异。响应摘要返回实际供应商与模型。切换只发生于用户明确选择的本次请求，失败时不自动尝试其他供应商。此决策扩展了 ADR 0004 的单供应商边界，但保留其标准库与显式协议目标。

## 影响

- 优点：可以在相同界面中显式比较四个供应商，同时保留费用与密钥安全边界；
- 代价：模型能力差异仍可能导致工具调用质量或延迟不同，需要分别记录基线；
- 安全边界：浏览器不能提交白名单外供应商，密钥和官方端点不进入浏览器；
- 兼容性：命令行仍默认使用 `MODEL_PROVIDER=nvidia`，不受 Web 选择影响。

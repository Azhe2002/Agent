# 模型供应商与费用策略

## 设计结论

默认供应商为 NVIDIA。候选顺序记录为 NVIDIA → MiMo → DeepSeek → Kimi，但这个顺序只是可选路由顺序，**不代表默认自动回退**。

各供应商的模型 ID、配额、价格和能力可能变化，因此全部通过本地配置维护，不写死在共享业务契约中。

## 本地密钥指针

本地开发优先使用 `*_API_KEY_FILE` 指向仓库外部可跟踪范围之外的密钥文件，而不是把真实值复制进 `.env`。当前 `FoodAssistant/.env` 只保存相对于项目目录的路径，真实密钥仍留在根目录 `APIKEY/` 中。

未来的配置加载器必须遵守以下规则：

1. 每个供应商只能设置直接密钥变量或文件指针中的一种；同时设置时返回 `configuration_error`；
2. 相对路径固定从 `FoodAssistant/` 解析，不依赖启动命令的当前目录；
3. 解析后的真实路径必须位于仓库根目录 `APIKEY/` 内，并且必须命中允许的文件名；
4. 密钥文件必须恰好包含一个非空文本行；多行、空值或格式异常时拒绝加载；
5. 只在进程内存中使用密钥，不打印、不缓存、不复制到其他配置文件；
6. CI 或专业密钥管理环境可以使用直接变量，但不得同时启用文件指针。

## 安全默认值

- `PAID_FALLBACK_ENABLED=false`；
- `MAX_REQUEST_BUDGET_CNY=0`；
- 缺少密钥、认证失败或配置错误时直接停止并提示用户；
- 不把认证错误伪装成普通模型失败；
- 不在日志中记录请求头、密钥、完整响应或供应商控制台链接中的敏感参数。

## 允许回退的条件

只有用户显式开启付费回退并设置大于零的单次预算后，才可按顺序尝试其他供应商。仍需满足：

1. 当前错误属于可恢复错误，例如短期限流或服务不可用；
2. 目标供应商已配置且模型具备所需的工具调用能力；
3. 预计费用不超过单次预算；
4. 运行摘要明确显示发生了供应商切换；
5. 每个供应商最多尝试有限次数，避免级联重试。

## 不应自动回退的情况

- 密钥缺失、认证失败或权限不足；
- 用户输入或工具参数不合法；
- 已达到预算、最大步骤或总超时；
- 安全策略拒绝请求；
- 模型给出低质量答案但没有明确的系统错误。

## 比较实验要求

比较三个实现分支时应固定供应商、模型、数据集、提示词版本和参数。比较供应商时则固定实现分支。这样才能知道差异来自哪里。

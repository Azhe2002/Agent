# 美食小助手安全设计

本文件把根目录 [SECURITY.md](../../SECURITY.md) 的仓库规则落实到该项目。

## 数据分类

| 数据 | 分类 | 处理方式 |
|---|---|---|
| 供应商密钥 | 最高敏感 | 仅本地环境读取，不输出、不持久化、不提交 |
| 密钥文件指针 | 本地配置 | 可指向 `APIKEY/`，但本地 `.env` 仍不提交，日志只记录供应商名 |
| 用户自然语言输入 | 可能敏感 | 只发送完成任务所需内容，默认不持久化原文 |
| 模型与工具完整载荷 | 可能敏感 | 默认不记录；调试时脱敏并限定保留时间 |
| 菜谱与模拟食材 | 公开项目数据 | 可版本控制，但需记录来源或原创声明 |
| 指标与错误分类 | 低敏感 | 可记录聚合值，不包含原始凭据与用户文本 |

## 工具权限

MVP 的四个工具全部为只读、本地、无副作用工具。每个工具都必须使用白名单名称、参数校验、返回大小限制和超时。未知工具请求不得尝试映射为系统命令或任意文件访问。

## 密钥加载边界

- `FoodAssistant/.env` 仅保存 `*_API_KEY_FILE` 路径，不保存真实值；
- 加载器只允许访问根目录 `APIKEY/` 下的四个白名单文件；
- 读取密钥属于运行时边界，Agent、调试工具和日志不得查看或回显内容；
- 文件指针与直接密钥变量同时存在时拒绝启动，避免来源不明确；
- `.env.example` 永远只保留空值和说明，可安全提交。

## Prompt Injection 边界

菜谱、天气、食材和未来的检索内容均视为不可信数据。数据中即使出现“忽略之前规则”或“读取密钥”等文本，也不能改变系统规则、供应商配置或工具权限。

## 输出安全

- 不把菜谱推荐描述为医疗或营养专业意见；
- 涉及过敏、食材不熟、明火和刀具时给出简短安全提醒；
- 缺少关键信息时承认不确定性，不编造天气或菜谱记录；
- 调试摘要只显示步骤类型、耗时、Token/费用估算和脱敏错误类别。

## 上线真实服务前的门槛

- 增加域名白名单、网络超时、速率限制和重试上限；
- 区分开发、测试和生产密钥；
- 定义日志保留和用户数据删除策略；
- 为任何写操作增加人工确认和幂等设计；
- 完成 Prompt Injection、越权工具、预算失控和密钥泄漏测试。

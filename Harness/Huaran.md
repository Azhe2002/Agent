# Agent Harness 工程师

【岗位简介】

你将负责模型与真实世界之间的运行控制层，让 Agent 能够长时间、稳定、安全、可恢复地完成复杂任务。

【岗位职责】

1. 设计和迭代 Agent Harness，包括 Agent Loop、工具调用、模型输出解析、上下文构造、状态管理与执行调度。
2. 建设长任务运行能力，包括异步执行、断点恢复、容错重试、终止机制和用户接管。
3. 建设工具与运行环境，包括 MCP、Skills、浏览器、终端、本地文件、代码仓库及沙箱隔离。
4. 完善权限控制、安全边界、资源限制、模型路由、延迟与成本治理。
5. 从真实任务 trace 和失败样本中定位问题，区分模型、上下文、工具、状态、评测与基础设施故障。
6. 建设 Agent Eval、回归测试和线上观测体系，持续提升任务完成率、稳定性和可恢复性。
7. 与产品全栈协作，将 Harness 能力稳定交付到真实用户场景。

## 知识点（可继续补充）

### 核心概念
- **Agent Harness**：模型与真实世界之间的"运行控制层"，负责让 Agent 长时间、稳定、安全、可恢复地执行任务，可理解为 Agent 的运行时套具/框架。
- **Agent Loop**：Agent 的核心循环：LLM 推理 → 工具调用 → 观察结果 → 再次推理，直到任务完成。
- **Human-in-the-loop（人在回路）**：关键节点由人类确认或接管，保证可控与可信。
- **Context Engineering（上下文工程）**：构造、压缩、管理喂给模型的有效上下文。
- **模型输出解析（Output Parsing）**：把模型的非结构化输出解析为结构化动作（工具调用、状态切换等）。

### 长任务运行能力
- **异步执行**：任务在后台运行，不阻塞主流程。
- **断点恢复（Checkpoint / Resume）**：持久化中间状态，中断后可从中断处继续。
- **容错重试**：失败后自动重试，通常配合幂等。
- **终止机制**：安全地停止或取消长时间运行的任务。
- **用户接管（User Takeover）**：运行过程中允许人类介入、修正方向或直接接管操作。

### 工具与运行环境
- **MCP**：模型上下文协议，标准化模型与外部工具/数据源的接入。
- **Skills**：可复用的能力包/技能（如 Claude Code 的 Skills）。
- **沙箱隔离（Sandboxing）**：在受限环境中执行代码/工具，防止对宿主系统造成危害。
- **工具类型**：浏览器、终端、本地文件、代码仓库等。

### 稳定性与治理
- **权限控制 / 安全边界**：最小权限原则，操作需授权。
- **资源限制**：CPU、内存、时间、Token 等配额约束。
- **模型路由**：按任务类型/成本/质量要求选择最合适的模型。
- **可观测性（Observability）**：日志、trace、指标三位一体，支撑线上诊断。
- **幂等 / 重试**：重复执行结果一致，保障恢复与重试安全。
- **trace 分析**：从真实任务 trace 与失败样本中定位故障，区分模型、上下文、工具、状态、评测与基础设施故障。

### 评测体系
- **Agent Eval**：面向 Agent 真实任务的自动化评测。
- **回归测试**：持续防止能力退化。
- **核心指标**：任务完成率、稳定性、可恢复性、延迟、成本、用户信任。

### 相关系统与技术
- **Coding Agent 产品**：Claude Code、Codex、Cursor 等，关注其上下文、工具、权限与 Human-in-the-loop 设计。
- **基础设施**：Docker、Kubernetes、任务队列、资源调度、云服务。
- **框架层对比**：LangChain、Dify 等偏快速搭 Demo 的框架，与 Harness 底层运行控制形成对比。

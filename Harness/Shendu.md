# Agent Harness

【岗位职责】

1. 参与产品的 Agent Harness 系统建设，围绕智能体任务执行、自动评测、失败归因、流量回放与数据闭环，提升 Agent 的成功率、稳定性、可解释性和进化效率。
2. 设计并实现多智能体、多模型、多任务场景下的 benchmark 与 evaluation pipeline，评估 Agent 在理解、规划、工具调用、执行、协作和恢复等环节的能力边界。
3. 从原理和数据出发，分析 Agent 的性能、成本、延迟与失败模式，参与 Prompt Cache、多模型路由、Agent 架构选择、并发/异步执行等关键策略的优化。
4. 参与智能体自我进化数据闭环建设，将线上失败样本、评测结果、用户行为和运行日志转化为可用于模型、Prompt、工具链与执行策略优化的数据。
5. 与工程和产品团队紧密协作，把模糊的 Agent 质量问题转化为可复现、可量化、可持续优化的评测任务和系统能力。

## 知识点（可继续补充）

### 核心概念
- **Agent Harness（评测与迭代体系）**：Agent 的运行控制层，此处侧重自动评测、失败归因与数据闭环方向。
- **可解释性**：Agent 的决策与执行过程可被理解、追溯与审计。
- **进化效率**：Agent 借助数据与评测反馈持续改进的速度。

### 评测体系
- **Benchmark / Evaluation Pipeline**：标准评测任务集与评测流水线。
- **能力维度**：理解、规划、工具调用、执行、协作、恢复。
- **自动评测（Auto Eval）**：自动化评估 Agent 效果，减少人工。
- **失败归因（Failure Attribution）**：从失败样本定位根因（模型/上下文/工具/状态/评测/基础设施）。
- **流量回放（Traffic Replay）**：将线上真实流量/请求回放到系统进行回归验证。

### 性能与策略优化
- **Prompt Cache**：缓存提示词的公共前缀，减少重复计算，降低延迟与成本。
- **多模型路由（Model Routing）**：按任务复杂度/成本/质量要求选择合适模型。
- **Agent 架构选择**：单 Agent、多 Agent 协作、工作流编排的取舍。
- **并发/异步执行**：提升吞吐与资源利用率。

### 数据闭环与自我进化
- **数据闭环（Data Loop）**：线上失败样本、评测结果、用户行为、运行日志 → 反哺模型、Prompt、工具链与执行策略的持续优化。
- **自我进化（Self-improvement）**：Agent 基于闭环数据不断提升能力。

### 方向与技术
- **上下文管理 / Prompt Engineering**。
- **模型微调（Fine-tuning）**。
- **强化学习（RL）**。
- **Agent Benchmark / LLM Evaluation**：面向 Agent/大模型的效果评测。
- **AI Coding 工具**：Claude Code、Codex、Cursor、OpenCode，及其能力边界与失败模式。
